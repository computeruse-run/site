Keep the SDK. Collapse three meters into one.

Browser Use is the best open-source agent SDK out there — we recommend it and ship it natively. The pain isn't the SDK; it's Browser Use Cloud's three-layer pricing (browser time + LLM step + per-task) that makes long-running scrapes and complex agents expensive in ways you can't predict from the docs. We bill per active second. One meter. Everything included.

TL;DR
  • ▸ The Browser Use SDK stays. You only change a CDP endpoint URL. Your agent class, prompts, LLM config, custom tools — all unchanged.
  • ▸ Browser Use Cloud bills three meters: browser-time + LLM-step + per-task. We bill one: per active second. ~7× cheaper on a standard agent task ($0.15 → $0.01).
  • ▸ CAPTCHA + residential IP included on every plan. Browser Use Cloud includes them too — but the bill variance comes from the LLM-step meter, not the add-ons.
  • ▸ All 15+ LLM providers Browser Use already supports keep working. We don't touch the model layer.

When you should not switch.

  • ▸ You already self-host the Browser Use SDK on your own infrastructure and your bill is small. If it works, it works.
  • ▸ You use Browser Use Cloud's no-code agent builder dashboard heavily. That dashboard is their product; we don't ship an equivalent (we're SDK-first).
  • ▸ Your agent runs short, simple tasks (under a minute, under 5 LLM steps). The three-meter bill stays small for those; the savings on switching are real but not huge.

When you should switch.

  • ▸ Your Browser Use Cloud bill has crept past $100/month and you can't tell which meter is driving it.
  • ▸ Your agent runs long, multi-step tasks — anything over 5 minutes wall-clock or 20+ LLM decision steps — where the three-meter math compounds.
  • ▸ You fan out to 10+ concurrent sandboxes for scraping; plan caps on Browser Use Cloud start to bite.
  • ▸ You also want a non-Browser-Use path open — Claude Computer Use, OpenAI Operator, plain Playwright — without managing two clouds.
Three real scenarios

What the swap actually feels like.

Scenario 1 · Daily e-commerce price scrape across 50 SKUs

Today (Browser Use Cloud): Each SKU takes ~3 minutes wall-clock and ~6 LLM steps. 50 SKUs × 30 days = 1,500 tasks/month. The bill stacks: browser-time at ~$0.05/task, LLM step at ~$0.04/task, per-task fee at ~$0.06. That's $0.15/task × 1,500 = $225/month plus your LLM tokens.

Pain: the LLM-step meter is the unpredictable one. A site that changed its layout last week pushes step count from 6 to 12 per SKU; your bill silently doubles before anyone notices.

After switching: Same Browser Use SDK code, new CDP endpoint. Per-active-second metering: 3 min × 35% active = 63 active seconds × $0.000056 = ~$0.0035/task. 1,500 tasks × $0.0035 = ~$5/month, plus the same LLM tokens you were paying anyway. Roll-up: $225 → $5. Step-count variance no longer changes the bill at all because we don't meter per-step.

Scenario 2 · AI data pipeline pulling job listings nightly

Today (Browser Use Cloud): One batch job runs from 2-6am nightly. The agent navigates 200 job pages, extracts structured data, hits ~3 CAPTCHAs along the way. Each page is ~8 LLM steps. The per-task fee adds up because each page is a task — 200 tasks × $0.06 = $12/night just on per-task overhead.

Pain: the per-task fee is the line item that grew the fastest as your scrape coverage expanded.

After switching: We don't have a per-task fee. One persistent sandbox handles all 200 pages in sequence; you pay for the active seconds, nothing else. Monthly bill: ~$15 versus ~$370. The Browser Use SDK code is unchanged; the only thing different is the connection URL.

Scenario 3 · A growth team running ad-hoc one-off agent tasks

Today (Browser Use Cloud): Five marketers each kick off 3-4 agent runs per day. Mostly short — pull competitor pricing, check a partner's catalog, summarize a press release. Bill: ~$80/month with most of it being per-task fees on short tasks.

Pain: per-task fee dominates when tasks are short. A 30-second agent run pays the same per-task fee as a 30-minute one.

After switching: Free tier (100 active hours/mo) covers ~5,700 short tasks/month before you even hit Pro. The growth team's whole usage probably fits in Free. Bill drops to $0.

Migration

Change the CDP URL. Done.

Browser Use SDK reads a CDP endpoint URL from its configuration — Browser Use Cloud sets that to their hosted endpoint by default. To migrate, you change the endpoint to ours and the rest of your Agent class, prompts, LLM client, and custom tools stay exactly the same.

The SDK doesn't know which cloud it's talking to. As long as the endpoint speaks CDP — which ours does, natively — the agent runs. Browser Use's built-in step recorder, plan output, and screenshot loop all work without modification.

For teams using Browser Use's hosted agent dashboard (the web UI on browser-use.com), we don't ship an equivalent. The dashboard is Browser Use Cloud's value-add for non-developers; our equivalent is the SDK + your own dashboard. If the dashboard is a hard requirement, stay on Browser Use Cloud. If you're SDK-first anyway, you'll lose nothing in the switch.

A migration cookbook with verbatim diffs against the Browser Use quickstart ships with the SDK at github.com/computeruse-run/sdk.

Common questions.

Do I have to stop using the Browser Use SDK?+
No. Browser Use SDK is what we recommend. You only swap the underlying CDP endpoint URL — your agent class, prompts, LLM provider config, custom tools all stay identical. The SDK doesn't even know it's talking to a different cloud.
Why is the Browser Use Cloud bill so unpredictable?+
Three meters stacked: browser-time, LLM step, and per-task surcharge. A site layout change that pushes step count from 6 to 12 silently doubles the LLM-step line on your invoice. Our single per-active-second meter doesn't react to step count, so the bill stays predictable.
Do you support all the LLMs Browser Use supports?+
Yes. The LLM layer is Browser Use's code, not ours; we only provide the browser sandbox. Any provider Browser Use already wraps (Anthropic, OpenAI, Google, Mistral, Together, Groq, 15+ others) works unchanged.
What about Browser Use's hosted dashboard (replay, share, no-code builder)?+
We ship a comparable live view URL and session recording (Pro 7-day, Team 30-day). The hosted agent dashboard is Browser Use Cloud's product, not ours; we focus on the sandbox + SDK. For teams that want a no-code agent builder, Browser Use Cloud is the better fit.
Can I self-host?+
Yes. The runtime is Apache 2.0 and Team includes the self-host Docker license. Browser Use SDK has always been self-hostable; we're the cloud sandbox layer it talks to.
