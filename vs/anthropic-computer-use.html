Anthropic's Computer Use is a model capability. To actually use it in production, you have to stand up the browser, the screenshot loop, the residential IP, the CAPTCHA solver, the sandbox isolation, and the cluster that runs them all. We do that part. Your Claude code and tool schema stay exactly the same.

TL;DR
  • ▸ Anthropic provides the Computer Use model; you provide everything that runs around it. We provide everything that runs around it.
  • ▸ Your Claude tool schema is unchanged. Only the execution backend swaps — from docker run anthropic-quickstarts/computer-use-demo to a managed sandbox on us.
  • ▸ A standard agent task drops from ~$0.20 (compute + ops) on the self-hosted path to ~$0.01 on us. ~10× cheaper for typical RPA workloads.
  • ▸ Concurrency goes from "one Docker, one session" to 25 concurrent sandboxes on Pro, unlimited on Team. Cold start drops from ~30s (Docker boot) to ~1.8s (pre-warmed pool).

When you should not switch.

  • ▸ Your Claude usage is text-only — no browser actions, no Computer Use tool. You don't need a browser cloud at all; just use the Anthropic API directly.
  • ▸ You run one Computer Use task per day for fun, on your laptop. The reference Docker container is free and works fine for that.
  • ▸ Your security policy forbids any third-party cloud touching the browser session, and you can't run the self-host Docker license either. (In that case, run Anthropic's reference Docker on your infra — that's what it's for.)

When you should switch.

  • ▸ You're running Claude Computer Use against a real website that fights bots — needs residential IP, CAPTCHA solving, browser fingerprint variation.
  • ▸ You've outgrown one Docker container — you need to run 10+ agent tasks in parallel and the reference setup doesn't scale.
  • ▸ Your monthly Anthropic + infrastructure bill has crossed $500 and you've started doing the per-task cost math.
  • ▸ You ship a product where end-users see the browser session in real time (live view URL).
  • ▸ You want one API across Claude + OpenAI Operator + Gemini, not three different action handlers.

Migration

Change one connection string. That's it.

Anthropic's reference implementation has your Computer Use loop talking to a local Docker container over HTTP at http://localhost:8080 (or wherever you mounted it). The tool schema you send to Claude is the standard computer_20241022 type with the same action enum.

To migrate: replace the localhost URL with https://api.computeruse.run/v1/sandboxes/{id}/actions and pass your account API key as a bearer header. Every action shape — screenshot, click, type, scroll — is one-to-one with what the reference Docker accepts. Your Claude call doesn't move; your tool result handler doesn't move. The only thing that changes is where the action gets executed.

You keep your Anthropic API key; the Claude model call stays with Anthropic. We only run the browser side. That separation matters for compliance — your model traffic and your sandbox traffic flow through two independent vendors, easier to audit.

A migration cookbook (verbatim diffs against the Anthropic quickstart) ships with the SDK at github.com/computeruse-dev/sdk.

Common questions.

Do I need to change my Claude code?+
No. The Anthropic tool schema is unchanged. The only thing that moves is the execution backend — from the reference Docker container Anthropic ships to a managed cloud sandbox. Same model calls, same tool definition, same coordinate space.
Do I keep my Anthropic API key?+
Yes. You bring your own Anthropic API key; we never see your model calls. We sit on the execution side only — Chromium, screenshot pipeline, action loop, residential IP. Your Claude tokens are billed by Anthropic directly.
What about concurrency?+
Anthropic's Docker runs one session at a time. We run 25 concurrent on Pro, unlimited on Team. Cold start ~1.8s (pre-warmed pool) versus ~30s to boot another Docker on your own infrastructure.
Can I still self-host?+
Yes. The runtime is Apache 2.0. Self-host it on your own VPC and you get the multi-provider SDK + the pre-configured sandbox image, without our cloud orchestration. Team includes the self-host license; the runtime itself is free.
What about Anthropic releasing their own hosted Computer Use?+
Likely within 12-18 months. Our hedge: (a) multi-provider (Claude + OpenAI + Gemini behind one SDK — Anthropic will only host Claude), (b) per-active-second billing (Anthropic's hosted offering will almost certainly be per-hour, matching their API patterns), (c) Apache-2.0 self-host path. If Anthropic's hosted version is cheaper and you only use Claude, switching back will be easy.
